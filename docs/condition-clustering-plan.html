Section 1

The Final Decision: Multi-Layer Auto-Clustering

After researching ICF, APTA, DRGs, HCC, CCSR, SNOMED-CT, and PT clinical reasoning patterns, the answer is clear: no single dimension is enough. Conditions need to be clustered on multiple axes simultaneously.

The Three-Layer Model Layer 1 (Primary): Body Region — how PTs think, examine, and treat. Always visible.
Layer 2 (Within region): Pathology Type + Severity — determines treatment approach.
Layer 3 (Cross-region): Kinetic Chain — the differentiator. Connects related conditions across body regions.

Why body region first? Research on PT clinical reasoning (Edwards et al., 2004; Jensen et al., 2000) consistently shows experienced PTs organize by anatomical pattern first, then refine by pathophysiology. Fighting this mental model creates friction. Working with it creates flow.

Why not just body region? Because a degenerative knee and a post-surgical knee are the same region but need completely different treatment. And because hip weakness causing knee pain is invisible to a body-region-only system.

The UX Principle Zero extra work for the physiotherapist. Conditions auto-cluster when added. The PT sees the grouped result and can override with one tap. Research (Johnson & Goldstein, 2003) shows smart defaults are accepted 80%+ of the time.

Hierarchical Suppression (from CMS-HCC model) When a more specific diagnosis exists, suppress the less specific one. If a patient has "L4-5 disc herniation with left L5 radiculopathy" (M51.16), don't also show "Non-specific low back pain" (M54.5) as a separate condition in the cluster. The specific diagnosis subsumes the general one.
Layer 3 — Cross-Region

Kinetic Chain Relationships

This is the differentiator. When a patient has conditions in multiple regions, the system automatically identifies biomechanical relationships between them.

Example: Patient has knee pain (patellofemoral syndrome) + hip pain (gluteal tendinopathy). The system shows:

Linked via Lower Quarter Kinetic Chain Hip abductor weakness (gluteal tendinopathy) is a known biomechanical contributor to patellofemoral syndrome. Strengthening hip abductors may address both conditions. Consider an integrated treatment plan.

Evidence: Powers CM (2010), JOSPT 40(2) · Confidence: 90%

This doesn't auto-merge the conditions into one cluster (they stay in their own body regions). Instead, it shows a relationship link between them — visual, informative, and actionable.

Kinetic Chain: The Complete Data Model

Key Finding: No Ready-Made Database Exists There is no open database of kinetic chain relationships. The knowledge lives fragmented across textbooks (Myers, Vleeming, Janda, Sahrmann) and hundreds of research papers. Building this as a structured knowledge graph would be novel in the clinical software space.

Recommended Approach: Static JSON Knowledge Graph

Since kinetic chain data changes infrequently (textbook-level knowledge), a static JSON file embedded in the app is the right approach for Phase 1. No external API needed. It's fast, offline-capable, and fully auditable.

The graph has ~20 body region nodes, ~80-100 chain relationship edges, and ~50-100 condition-chain mappings for common PT conditions.

Data Structure

Three core entities:

  • Body Region Nodes (~20): foot, ankle, lower leg, knee, thigh, hip, pelvis, lumbar, thoracolumbar, thoracic, cervical, shoulder, elbow, wrist/hand, cranium + sub-regions
  • Chain Relationship Edges (~80-100): connecting regions via named chains with direction, mechanism type, and evidence level
  • Condition-Chain Mappings (~50-100): mapping common conditions to which chains they affect and what commonly co-occurs

Section 5

How Auto-Clustering Works

When a Condition is Added to a Patient

  1. Body region lookup — ICD-10 code or condition identifier maps to one of 12 body regions via ~200 rule table. Instant, deterministic.
  2. Same-region grouping — If patient already has active conditions in that region, auto-group them. Show as one cluster labeled by region.
  3. Hierarchical suppression — If new condition is more specific than existing one (e.g., M51.16 disc herniation subsumes M54.5 non-specific LBP), suppress the general one.
  4. Pathology & severity classification — Infer from ICD-10 category and clinical data.
  5. Kinetic chain scan — Check all other active conditions against kinetic chain graph. If a relationship exists (confidence ≥70%), show a link.

Override Scenarios

  • Ungroup: PT decides lumbar disc and sciatica need separate protocols → one tap to split
  • Dismiss chain link: PT disagrees hip is a factor → dismiss the suggestion (system learns)
  • Manual group across regions: PT wants to combine lumbar + knee into one treatment plan → drag to merge (rare but possible)
Section 6

Implementation Phases

Phase 1 — Ship Now

Body Region Auto-Clustering + Static Kinetic Chain Graph

  • ICD-10 → Body Region lookup table: ~200 rules covering 95% of PT conditions
  • Auto-group same-region conditions: When a condition is added, it joins the existing cluster for that region
  • Pathology type tagging: From ICD-10 category ranges
  • Static kinetic chain JSON: ~20 nodes, ~80 edges, curated from Myers + Vleeming + Janda
  • Chain link display: When conditions span related regions, show the link
  • Hierarchical suppression: More specific diagnosis hides less specific one

Effort: Manageable. The lookup table + JSON graph is manual curation (clinical team), the UI is engineering.

Phase 2 — 3-6 Months

Learning + Co-occurrence

  • Track PT overrides: When they ungroup, regroup, or dismiss chain links — log it
  • Co-occurrence mining: After sufficient patient data, discover which conditions frequently co-exist
  • Smart suggestions: "Patients with condition A often also have condition B — consider screening"
  • Condition-chain mapping expansion: From initial ~50 to ~200+ based on real usage data
Phase 3 — 6-12 Months

Predictive Intelligence

  • Predictive secondary screening: "This patient's ankle condition + kinetic chain data suggests hip screening may be valuable"
  • Treatment overlap detection: "These 3 exercises address both conditions — consolidate"
  • Outcome-based refinement: Which groupings lead to better outcomes?
  • Severity auto-inference: From clinical assessment data
